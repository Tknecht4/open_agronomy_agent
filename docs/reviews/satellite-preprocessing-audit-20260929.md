# HLS preprocessing and QA audit — 2026-09-29

Status: bounded development candidate on `codex/geospatial-preprocessing`, based on merged `f2fb44a`. This is a code and synthetic-fixture audit, with a read-only check of three retained HLS chip arrays. It is not a field accuracy or agronomic validation. Raw source assets, historical cache bytes, and historical receipts were not changed.

## Reference and scope

The active path selects one public HLS v2 S30 or L30 scene through Planetary Computer, samples six 30 m reflectance bands and Fmask on the source lattice, applies QA, and reports NDVI/NDMI over a saved polygon or explicit point support. The source-grid/weighted-support implementation and earlier checks remain in `imagery_analytics.py`, `imagery_sampling.py`, and `geospatial/raster.py`. The April 2026 [NASA HLS v2 user guide](https://lpdaac.usgs.gov/documents/1698/HLS_User_Guide_V2.pdf), especially Tables 6, 7 and 9, is the product encoding and QA reference. NASA's [L30](https://hls.gsfc.nasa.gov/products-description/l30/) and [S30](https://hls.gsfc.nasa.gov/products-description/s30/) product pages specify a 12000 saturation flag. NASA's [algorithms](https://hls.gsfc.nasa.gov/algorithms/) and [atmospheric correction](https://hls.gsfc.nasa.gov/atmospheric-correction/) pages describe the existing atmospheric correction, nadir BRDF normalization and S30 bandpass adjustment. These transforms are supplied by HLS and are not repeated locally.

## Observations and this development slice

| Observation at baseline | Consequence | Change |
|---|---|---|
| STAC scale/offset were checked, but opened raster headers could have a conflicting dtype, nodata or scale. Fmask was cast to `uint8` regardless of its source dtype. | An incompatible layer could silently become QA bits or scaled reflectance. | Check actual COG count/grid and radiometry before reading: int16/-9999 for reflectance, uint8/255 for Fmask. Missing nodata tags remain allowed, with explicit fill values and tile extent still masked. GDAL scale/offset tags must agree with HLS when nondefault for reflectance, and be identity for categorical Fmask. Check STAC dtype/nodata and Fmask scale/offset when supplied. Record actual COG tags separately from the applied reflectance scale. Incompatibility returns typed `unavailable` without rendering a signed URL. |
| Fmask bit 0 was labeled “cirrus.” Table 9 reserves bit 0 and says it is unused in HLS v2; cirrus is included in the cloud detection. | A diagnostic reason could misstate the source observation. | Rename bit 0 to `reserved_bit_0`; conservatively exclude it if unexpectedly set. Retain cloud, adjacency, shadow, snow and high-aerosol exclusions. QA bits can overlap. |
| An encoded 12000 saturation flag could enter clear area and indices. Water bit 5 was retained but invisible as a separate observation. | Saturated reflectance could enter indices; water could be mistaken for absent when no cloud was flagged. | Exclude the 12000 flag with its own area reason and values above the documented flag as unsupported high DN. This is an encoded-product policy, not a physical reflectance ceiling. Report `water_flag_area_m2` separately; water can remain QA clear if other checks pass. A crop/land suitability policy is a separate decision. |
| A negative input reflectance with a small/negative denominator could yield an NDVI or NDMI beyond the usual normalized range. | Clear QA area could imply valid index support even when the ratio had no interpretable value. | Preserve the clear source observation but compute each index only if both input reflectances are nonnegative and their sum exceeds `1e-6`. Report `index_undefined_area_m2_by_reason` for negative inputs and nonpositive/near-zero sum. Index statistics continue to report their own support area, which may be smaller than QA clear area. This is an explicit index eligibility rule, not a universal assertion that negative HLS reflectance is corrupt. |
| Prior NPZ chips kept only QA-masked reflectance; a cloudy pixel's original DN could not be inspected or processed with another declared QA policy. | Alternate QA experiments required reacquisition and could not be replayed from the cache. | New v4 NPZ chips also retain `raw_dn` as validated int16 pre-QA source-window values and `source_invalid_mask` for fill, raster mask and outside-tile support. Fmask stays in its raw categorical array. Both new arrays enter the chip binding hash. Metadata labels their roles and applied reflectance scale. A cloud-excluded pixel retains its DN while the processed reflectance remains NaN; off-tile numeric placeholders are still invalid. The dynamic 16 MiB per-chip admission remains in force; a 224×224 context fixture stayed below it. |

The polygon and point processing identities advanced to v4. Request hashes and process hashes therefore miss prior v3 cache entries. This preserves historical files and allows an exact source/processing comparison; offline requests without a v4 chip return `blocked_offline`. The point receipt validator uses the new process constant. The frontend now labels QA clear area separately from index support, shows water flags, and reveals positive index support exclusions. The receipt API remains additive.

## Verification and observational limit

Focused raster tests: 43 passed using the isolated optional imagery environment, including incompatible Fmask dtype, reflectance dtype/nodata, GDAL/Fmask scale and offset, STAC nodata and Fmask tags, reserved bit, saturation, unsupported high DN, water, negative reflectance and pre-QA replay arrays. Storage/API compatibility: 45 passed in the base service environment. Frontend typecheck and 73 focused component tests passed. These checks use local fixtures; no new live HLS COG was acquired in this slice.

A read-only aggregate inspection of three retained, previously processed HLS chip arrays found 102 QA-clear supported pixels. Those arrays contained zero NDVI/NDMI negative-input or near-zero-sum cases and zero QA-clear water flags. This sample shows no index-support change for those retained pixels. The historical arrays already masked excluded reflectance and did not retain source DN, so they cannot verify source COG header behavior, replay QA, or quantify pre-mask saturation. Their sampled geometries are research AOIs, not surveyed field boundaries. No location or raw artifact is included here.

## Staged gap ledger

1. **Next source qualification:** Probe actual S30 and L30 COGs from the configured public asset host, including all six raster headers, STAC `raster:bands`, fill values, scale tags and source checksums. Record a bounded acquisition receipt and reject contradictions. The synthetic tests prove behavior when conflicting metadata is supplied; they do not prove how every provider granule is encoded.
2. **Next scene QA study:** Evaluate field-support thresholds and scene choice using source-distinct observations across seasons and land covers. Compare high-aerosol and adjacency exclusion sensitivity, mixed QA bits, snow, water, saturation and missing pixels. Do not infer field clear fraction from scene cloud percentage, or agricultural land status solely from Fmask water. Establish a documented minimum support policy before operational interpretations.
3. **Next temporal/sensor study:** Test L30/S30 comparability, co-registration, bandpass residuals and seasonal index stability against independent reference observations. HLS supplies NBAR and harmonization, but local one-scene indices do not establish crop condition, yield, stress diagnosis or field-wide precision. Keep acquisition, source observations, index model output and interpretation distinct.
4. **Product path later:** Add source-aware metadata/known-issue admission, temporal composites and explicit uncertainty only after the first two gates; retain exact process/source identity and historical cache reads. A multisensor grid or land/crop mask requires an explicit policy and evidence, not a silent change to the HLS QA meaning.

Changed: header/STAC radiometry validation, Fmask reason correction, saturation/water reporting, bounded index eligibility, pre-QA DN retention, v4 cache identity and concise UI QA display. Verified: local focused tests and read-only aggregate chip diagnostic above. Residual risk: actual COG encoding and scientific field performance remain unqualified; old offline cache entries do not satisfy v4. Memory delta: none.

## Receipt consistency review repair

Independent review reproduced a v4 point receipt that simultaneously claimed valid index support and rejection of the same area. Backend and frontend now enforce conservation for each NDVI/NDMI partition: valid index support plus negative-input and nonpositive-sum areas equals QA-clear area within the documented numerical tolerance. Missing, extra, nonfinite, overlapping or inconsistent reason partitions are rejected; a coherent zero-index-support partition remains valid. The targeted repaired slice passed 43 raster, 52 API/storage and 80 imagery component tests plus typecheck. This is a receipt-integrity check, not validation of field accuracy.
