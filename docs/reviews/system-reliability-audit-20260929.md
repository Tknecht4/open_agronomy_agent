# System reliability audit and repair — 2026-09-29

Reference: main `c6f3fa1a3a6858a413b6cc6bb6dc138d1b7fa329`. This bounded audit follows the geospatial feature rounds and examines scientific-result admission, persistence and recovery. It is not a claim that every subsystem has been audited or that field science has been validated.

## Reproduced weaknesses and repairs

| Boundary | Observed failure on reference | Repair and regression evidence |
| --- | --- | --- |
| Polygon imagery → app | A locally processed HLS chip with a deliberately reindexed receipt claiming 150% clear area was served as `available`, including its preview URL. Hashes were valid; support meaning was contradictory. | Shared current HLS QA checks at cache, worker-readback and direct-preview boundaries; browser checks before rendering or fetching previews. HTTP failure cases cover area/fraction, status, version, provider, grid, index range and support balance. The same actual-raster probe now returns `storage_unavailable` without a preview. |
| Backup → relocated object store | A validated backup restored files under the new root but left attachment database URIs at the source root. The restored `LocalObjectStore` rejected its own attachment. | Validate store-owned references and bytes, then rebase absolute attachment and legacy export references in the staged database. The unchanged source archive remains the reference; a transformation receipt records the new staged database hash. Existing transaction recovery binds that transformed hash. Tests read and delete restored attachments through the actual object store and exercise interrupted commit recovery. |
| SQLite snapshot → artifact copy | Deleting an attachment after the database snapshot and before the artifact copy could publish an archive whose manifest passed validation but could not restore a live attachment. | Creation validates snapshot references against copied artifacts before publishing the backup. Missing files and size/hash mismatches fail closed; restore performs these checks for older backups too. Concurrent-deletion and payload-mutation regressions cover the gap. |

The imagery validator shares the point/polygon index QA contract. Clear support must fit total support, each normalized index must lie within its defined range (with numerical tolerance), and valid index area plus its mutually exclusive undefined-domain areas must equal QA-clear area. Cloud-quality exclusion areas can overlap each other, but each must be disjoint from QA-clear support; their sum with nodata must at least account for all non-clear support. Water flags cannot include nodata. Exclusion sums are **not** reported as union areas. Independent review reproduced missing clear/exclusion disjointness checks; the shared backend and browser checks now enforce these bounds. Undefined indices remain null; water flags remain distinct from exclusions. Current process versions are required for app observations. Historical polygon records remain readable through the byte-integrity store as evidence and are not silently rewritten or upgraded.

Backup transformation is deliberately narrow: active attachment files must match database size/hash metadata; export files with recorded manifests must match those records. Missing or unsafe references are refused before target publication. Root-relative export references remain relative. Deleted attachment tombstones may legitimately have no file. Arbitrary text and provenance fields are not rewritten. Manifest digests detect byte changes; they are not authenticated signatures.

## Remaining weaknesses, in priority order

1. **Worker readiness and lifecycle.** Settings check that the configured Python executable exists, but the imagery availability response does not test its optional dependencies or ability to process a chip. Work runs synchronously under a process-local slot and a 150-second subprocess timeout. A durable job record, progress/cancellation contract and an explicit environment qualification probe would make failures and restarts easier to diagnose. This is source-inspected operational debt, not an observed data-loss claim.
2. **Recovery coverage across stores.** The backup primitive covers its SQLite database, artifact root and optional knowledge-update tree. The separately configured imagery cache is not automatically included, and terrain/selection operator products have their own locations. A shared product inventory and a declared backup-set manifest should identify included and omitted stores before retention or centralization work. Do not delete historical chips merely because they are outside the app backup.
3. **Quiescence during maintenance.** Reference checks catch inconsistent copied attachments/exports; they do not create one transaction spanning SQLite and every filesystem writer. Stop application writers for restore and for a reproducible maintenance backup. Historical exports without per-file hashes can be checked for presence, but not against an absent historical checksum. A managed maintenance/backup command and restore rehearsal remain useful next work.
4. **Scientific qualification beyond receipt consistency.** Coherent QA and reproducible chips do not establish inter-date co-registration, temporal-composite quality, field-edge purity, hydrological catchment completeness or crop-condition accuracy. Keep these as separately evaluated capabilities; use the existing seeded field geometries and independent observed data for qualification. This repair round uses local synthetic rasters and storage fixtures, with no new field queries or provider downloads.
